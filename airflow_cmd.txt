# AIRFLOW DOCKER - POWERSHELL COMMANDS CHEAT SHEET

This file contains the important PowerShell commands used to install,
run, configure, test, troubleshoot, and push the Apache Airflow Docker
project to GitHub.

============================================================

1. CHECK PREREQUISITES
   ============================================================

Check Docker version:

docker --version

Check Docker Compose:

docker compose version

Check Git:

git --version

Check current PowerShell directory:

Get-Location

List files and folders:

Get-ChildItem

============================================================
2. CREATE / ENTER AIRFLOW PROJECT DIRECTORY
===========================================

Create project folder:

mkdir airflow-docker

Move into the project:

cd airflow-docker

Check current directory:

Get-Location

============================================================
3. CREATE AIRFLOW PROJECT FOLDERS
=================================

Create DAGs folder:

mkdir dags

Create logs folder:

mkdir logs

Create plugins folder:

mkdir plugins

Create config folder:

mkdir config

Check folders:

Get-ChildItem

============================================================
4. CREATE DOCKER COMPOSE FILE
=============================

Create the Docker Compose file:

New-Item docker-compose.yaml -ItemType File

Open it in Notepad:

notepad docker-compose.yaml

Paste the Airflow Docker Compose configuration into this file.

============================================================
5. CREATE ENVIRONMENT FILE
==========================

Create .env:

New-Item .env -ItemType File

Open .env:

notepad .env

Example:

AIRFLOW_EMAIL=[your_email@gmail.com](mailto:your_email@gmail.com)
GMAIL_APP_PASSWORD=your_gmail_app_password

IMPORTANT:
Never commit the real .env file to GitHub.

============================================================
6. CREATE .GITIGNORE
====================

Create .gitignore:

New-Item .gitignore -ItemType File

Open it:

notepad .gitignore

Recommended contents:

.env
**pycache**/
*.pyc
logs/
.DS_Store

============================================================
7. VALIDATE DOCKER COMPOSE FILE
===============================

Check whether docker-compose.yaml is valid:

docker compose config

If there is no configuration error, the YAML is valid.

============================================================
8. START AIRFLOW
================

Start all Airflow containers:

docker compose up -d

Start containers and rebuild images if required:

docker compose up -d --build

Check running containers:

docker compose ps

============================================================
9. CHECK AIRFLOW LOGS
=====================

Check all services:

docker compose logs

Check worker logs:

docker compose logs airflow-worker

Check scheduler logs:

docker compose logs airflow-scheduler

Check API server logs:

docker compose logs airflow-api-server

Show only the latest 100 lines:

docker compose logs airflow-worker --tail 100

Follow logs continuously:

docker compose logs -f airflow-worker

Stop following logs:

CTRL + C

============================================================
10. CHECK AIRFLOW VERSION
=========================

Run Airflow version inside worker:

docker compose exec airflow-worker airflow version

============================================================
11. CHECK AIRFLOW CONNECTIONS
=============================

List all connections:

docker compose exec airflow-worker airflow connections list

Get SMTP connection:

docker compose exec airflow-worker airflow connections get smtp_default

Get SMTP connection as JSON:

docker compose exec airflow-worker airflow connections get smtp_default --output json

============================================================
12. CREATE SMTP CONNECTION
==========================

Create the SMTP connection:

docker compose exec airflow-worker airflow connections add smtp_default `--conn-type smtp`
--conn-host smtp.gmail.com `--conn-port 587`
--conn-login "[your_email@gmail.com](mailto:your_email@gmail.com)" `
--conn-password "YOUR_APP_PASSWORD"

NOTE:
Do NOT save your real password in this file.

For a permanent Docker setup, prefer configuring the connection
through the environment variable:

AIRFLOW_CONN_SMTP_DEFAULT

Example structure:

smtp://EMAIL:APP_PASSWORD@smtp.gmail.com:587/

============================================================
13. TEST SMTP CONNECTION
========================

Test the SMTP connection from the Airflow worker:

docker compose exec airflow-worker python -c "from airflow.providers.smtp.hooks.smtp import SmtpHook; h=SmtpHook(smtp_conn_id='smtp_default'); h.get_conn(); print('SMTP CONNECTION SUCCESS')"

Expected result:

SMTP CONNECTION SUCCESS

============================================================
14. CHECK SMTP CONFIGURATION
============================

Check SMTP configuration:

docker compose exec airflow-worker airflow config get-value smtp smtp_host

Check SMTP port:

docker compose exec airflow-worker airflow config get-value smtp smtp_port

Check STARTTLS:

docker compose exec airflow-worker airflow config get-value smtp smtp_starttls

Check SSL:

docker compose exec airflow-worker airflow config get-value smtp smtp_ssl

============================================================
15. LIST AIRFLOW DAGS
=====================

List all DAGs:

docker compose exec airflow-worker airflow dags list

Check a particular DAG:

docker compose exec airflow-worker airflow dags list | Select-String "email_failure_test"

============================================================
16. TEST DAG
============

Trigger a DAG manually:

docker compose exec airflow-worker airflow dags trigger email_failure_test

Check DAG details:

docker compose exec airflow-worker airflow dags show email_failure_test

============================================================
17. CHECK DAG TASKS
===================

List tasks:

docker compose exec airflow-worker airflow tasks list email_failure_test

Test a particular task:

docker compose exec airflow-worker airflow tasks test email_failure_test failing_task

============================================================
18. CHECK WORKER LOGS FOR DAG
=============================

Search worker logs for the DAG:

docker compose logs airflow-worker --tail 200 |
Select-String -Pattern "email_failure_test"

Search for errors:

docker compose logs airflow-worker --tail 200 |
Select-String -Pattern "ERROR|Exception|Traceback"

Search specifically for email/SMTP errors:

docker compose logs airflow-worker --tail 200 |
Select-String -Pattern "SMTP|smtp|email|notification"

============================================================
19. READ TASK LOG FILE
======================

Example:

docker compose exec airflow-worker cat "/opt/airflow/logs/dag_id=email_failure_test/run_id=RUN_ID/task_id=failing_task/attempt=1.log"

Replace RUN_ID with the actual DAG run ID.

============================================================
20. CHECK DAG RUN FROM AIRFLOW CLI
==================================

Depending on the Airflow version, some older CLI commands may not
be available.

To see available DAG commands:

docker compose exec airflow-worker airflow dags --help

To see available commands:

docker compose exec airflow-worker airflow --help

============================================================
21. CHECK CONTAINER STATUS
==========================

Show all containers:

docker compose ps

Check only worker:

docker compose ps airflow-worker

Check only scheduler:

docker compose ps airflow-scheduler

Check only PostgreSQL:

docker compose ps postgres

Check only Redis:

docker compose ps redis

============================================================
22. ENTER AIRFLOW WORKER CONTAINER
==================================

Open a shell inside worker:

docker compose exec airflow-worker bash

After entering the container:

airflow version

Exit:

exit

============================================================
23. CHECK PYTHON INSIDE AIRFLOW
===============================

Python version:

docker compose exec airflow-worker python --version

Check installed packages:

docker compose exec airflow-worker pip list

Check SMTP provider:

docker compose exec airflow-worker pip show apache-airflow-providers-smtp

============================================================
24. RESTART AIRFLOW
===================

Restart everything:

docker compose restart

Restart worker:

docker compose restart airflow-worker

Restart scheduler:

docker compose restart airflow-scheduler

Restart API server:

docker compose restart airflow-api-server

============================================================
25. STOP AIRFLOW
================

Stop containers:

docker compose stop

Start them again:

docker compose start

============================================================
26. STOP AND REMOVE CONTAINERS
==============================

Stop and remove containers:

docker compose down

Remove containers and networks:

docker compose down

============================================================
27. COMPLETE RESET
==================

WARNING:
This can remove your PostgreSQL data if volumes are removed.

Stop containers:

docker compose down

Remove containers, networks and volumes:

docker compose down -v

Then start again:

docker compose up -d

============================================================
28. VIEW DOCKER IMAGES
======================

List Docker images:

docker images

============================================================
29. VIEW DOCKER CONTAINERS
==========================

Running containers:

docker ps

All containers:

docker ps -a

============================================================
30. CLEAN UNUSED DOCKER RESOURCES
=================================

WARNING:
This removes unused Docker resources.

docker system prune

Check Git version:

git init

=============================

Check files:

git status

IMPORTANT:
Make sure .env is NOT shown as a file that will be committed.

============================================================
34. ADD FILES TO GIT
====================

Add all files:

git add .

Check staged files:

git status

============================================================
35. COMMIT PROJECT
==================

Create first commit:

Check commits:

git log --oneline

36. CONNECT LOCAL PROJECT TO GITHUB
===================================

Check existing remotes:

git remote -v

Add GitHub repository:

git remote add origin https://github.com/gautam2101/install-Apache-Airflow.git

Verify:

git remote -v

============================================================
37. SET MAIN BRANCH
===================

Rename current branch to main:

git branch -M main

Check branch:

git branch

============================================================
38. PUSH PROJECT TO GITHUB
==========================

First push:

git push -u origin main

For future pushes:

git add .

git commit -m "Update Airflow configuration"

git push

============================================================
39. CHECK GITHUB STATUS
=======================

Check local status:

git status

If everything is committed:

On branch main
nothing to commit, working tree clean

40. FUTURE WORKFLOW
===================

Whenever you change DAGs, Docker configuration, README, etc.:

Step 1:

git status

Step 2:

git add .

Step 3:

git commit -m "Describe your changes"

Step 4:

git push

============================================================
41. USEFUL GIT COMMANDS
=======================

Show current branch:

git branch

Show remote repository:

git remote -v

Show commit history:

git log --oneline

Show changes:

git diff

Show staged changes:

git diff --staged

Undo unstaged changes to a file:

git restore filename

Unstage a file:

git restore --staged filename

Show tracked files:

git ls-files

============================================================
42. IF GITHUB PUSH IS REJECTED
==============================

Pull changes first:

git pull --rebase origin main

Then:

git push

============================================================
43. IF YOU ACCIDENTALLY ADDED .ENV
==================================

Remove .env from Git tracking:

git rm --cached .env

Then commit:

git commit -m "Remove environment secrets"

Push:

git push

IMPORTANT:
If a real password was already pushed to GitHub, removing the file
is NOT enough. Immediately rotate/revoke the exposed password.

============================================================
46. IMPORTANT SECURITY RULES
============================

NEVER commit:

* Gmail password
* Gmail App Password
* API keys
* AWS access keys
* GCP service account private keys
* Database passwords
* Airflow Fernet keys
* JWT secrets

Use .env for local secrets.

Commit .env.example instead.
